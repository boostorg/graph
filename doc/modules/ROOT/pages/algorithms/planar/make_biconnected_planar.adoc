[#sec:make-biconnected-planar]
= make_biconnected_planar

Adds edges to a connected planar graph to make it biconnected while preserving planarity.

*Complexity:* _O(n)_ +
*Defined in:* `<boost/graph/make_biconnected_planar.hpp>`

----

| An undirected graph. The type `Graph` must be a model of
  xref:concepts/VertexListGraph.adoc[VertexListGraph],
  xref:concepts/IncidenceGraph.adoc[IncidenceGraph], and

| IN
| `EdgeIndexMap em`

| `AddEdgeVisitor vis`

[#migrating]
=== Migrating from `boost::make_biconnected_planar`

The `boost::make_biconnected_planar` overloads are deprecated. They took the visitor by non-const reference, which rejected temporaries and differed from the other BGL algorithms. Removal planned for Boost 1.95. Calls left unchanged then fail to compile instead of silently changing behavior.

. Replace `boost::make_biconnected_planar` with `boost::graph::make_biconnected_planar`. Unqualified calls need qualifying too, since argument dependent lookup only finds the deprecated overloads.
. If you read the visitor after the call, pass it as `std::ref(vis)`. Otherwise the algorithm works on a copy and your visitor is left unchanged.

[source,cpp]
----
// Before
make_biconnected_planar(g, embedding, get(edge_index, g), edge_updater);

// After
boost::graph::make_biconnected_planar(g, embedding, get(edge_index, g), std::ref(edge_updater));
----

== Description

A graph _G_ is biconnected if, for every pair of vertices _u,v_ in _G_, there is a cycle containing both _u_ and _v_.
Alternatively, a graph is biconnected if it is connected and cannot be made disconnected by removing any single vertex.
`make_biconnected_planar` takes a xref:algorithms/planar/make_connected.adoc[connected] xref:algorithms/planar/planar_graphs.adoc[planar] graph `g` as input and adds zero or more edges to make `g` biconnected while preserving planarity.

The default behavior of `make_biconnected_planar` is to modify the graph `g` by calling `add_edge(u,v,g)` for every pair of vertices _(u,v)_ where an edge needs to be added to make `g` biconnected.
This behavior can be overridden by providing a visitor as the `AddEdgeVisitor` parameter.
The only requirement for an `AddEdgeVisitor` is that it define a member function with the following signature:

[source,cpp]
----
template <typename Graph, typename Vertex>
void visit_vertex_pair(Vertex u, Vertex v, Graph& g);
----

This event point can also be used as a hook to update the underlying edge index map automatically as edges are added.
See the documentation for the xref:visitors/AddEdgeVisitor.adoc[AddEdgeVisitor] concept for more information.

See also link:../example/make_biconnected_planar.cpp[`example/make_biconnected_planar.cpp`].
